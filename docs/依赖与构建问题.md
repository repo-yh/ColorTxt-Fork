# 依赖与构建问题排查

> npm 11+ / Node 24 本机环境踩坑记录（2026-10-08）。CI 用 Node 22/npm 10（`.node-version`），不受 allow-* 收紧影响；将来 CI 升 Node 24 需在 workflow 加 `npm config set allow-remote all`。

## EALLOWGIT：git 协议依赖阻断

`npm update/install` 报 `EALLOWGIT`（`Fetching packages of type "git" have been disabled`）：

- 根因链：`mdict-js@10.0.1` → `fs-web@1.0.1` → `path@git://github.com/component/path.git#...`（GitHub 已关停 `git://` 端口，npm 新版默认禁 git 类型）
- 之前没报错只因 node_modules 已装好无需重拉
- **修复**：`package.json` overrides 加 `"fs-web": { "path": "0.12.7" }`（component/path 的官方 npm 镜像，代码一致）

## EALLOWREMOTE：remote tarball 阻断

`npm update` 报 `EALLOWREMOTE`（npm 11 默认 `allow-remote = "none"`）：

- 触发源：lockfile 里 `@protobufjs/inquire` 记录的是 npmmirror 完整 tarball URL（remote 类型）
- **修复**：重跑时加 `--allow-remote=all` 放行（如 `npm update tar --registry=https://registry.npmjs.org --allow-remote=all`）。放行后可能重装较多包但 lockfile 净变更很小，提交前 `git diff` 核对

## opencc 钉 1.3.1（Electron 35 加载即崩）

`npm update` 把 opencc 升到 1.4.2 后 dev 启动即 native 崩溃（退出码 `-36861`，日志末尾 `crashpad_client_win.cc(869) not connected`）：

- 根因：1.4.x 改用 scoped 包 `@opencc/opencc-win32-x64`（bazel 构建、非 NAPI）分发 native binding，Electron 35 加载即崩；项目 electron-rebuild 链路只适配 1.3.1 的 node-gyp 结构。**Node 24 能加载不代表 Electron 兼容**
- **修复**：package.json 钉 `"opencc": "1.3.1"`（去 `^` 防再升）+ `npm install` + `npm run postinstall`（electron-rebuild 重编）
- `crashpad not connected` 是崩溃伴生症状非原因；`ExperimentalWarning: SQLite` 无害
- **排查方法（可复用）**：临时 ESM 脚本用 `createRequire` 在 Electron 环境逐个 `require` native 模块（better-sqlite3、@node-rs/jieba、opencc、sqlite-vec、@caitun/speex），进程死在哪一行即崩溃源
- `allowScripts` 白名单会阻断 postinstall：electron、onnxruntime-node（二进制缺失则 AI/向量功能不可用）、better-sqlite3、esbuild、protobufjs、electron-winstaller 需逐个批准；手动跑 `node node_modules/electron/install.js` 若 dist/electron.exe 已存在会跳过下载，需先删 dist 再重跑

## Dependabot / npm audit 排查（2026-10-08）

- 推送后 Dependabot 从 21 增至 95 个（1 critical / 47 high / 38 moderate / 9 low），**唯一 critical 是 `tar`（node-tar）**：lockfile 记 7.5.13（≤7.5.20 有 6 个 advisory），但 node_modules 实际已装 7.5.22——Dependabot 扫 lockfile 故报警
- tar 三条引入路径全是**构建/开发工具链**（electron-builder→app-builder-lib、@electron/rebuild→node-gyp、@huggingface/transformers→onnxruntime-node），不进运行时，实际风险低
- **修法**：`npm update tar` 同步 lockfile 即可（node_modules 已是新版）
- 本机 npmmirror 镜像不支持安全查询 API，`npm audit` 必须加 `--registry=https://registry.npmjs.org`
- `npm audit fix` 后剩余 22 个（0 critical）**全部无法无破坏修复**：要么 `--force` 破坏性升级（electron 44、monaco-editor、pdfjs-dist、katex、sharp/transformers 4.x），要么上游未发修复（mdict-js 的 @xmldom/xmldom）。再跑 audit fix 无进展
