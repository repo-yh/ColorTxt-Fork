# 高亮词机制

> 整理自 2026-06 ~ 2026-10 开发记忆，以当前代码状态为准（fork 相对上游的核心自有增强之一，记录另见 `head 分支新独立功能.md`）。

## 存储结构

| 数据 | 位置 |
|------|------|
| 本书高亮词 | `colorTxt.file.meta` → `highlightWordsByIndex`（按文件路径独立） |
| 全局高亮词 | `colorTxt.ui.settings` → `globalHighlightWords` |
| 高亮色值 | `colorTxt.ui.settings` → `highlightColorsLight` / `highlightColorsDark` |
| 总开关 | `colorTxt.ui.settings` → `monacoCustomHighlight`（默认 true） |

**类型体系**（`src/renderer/src/stores/fileMetaStore.ts`）：

```typescript
type HighlightWord = { text: string; isRegex?: boolean };
// 内存与存储统一（当前最终态）：
type HighlightWordsByIndex = Record<string, HighlightWord[][]>;
// 外层键 = 色值索引；外层数组 = 该颜色下的词组；内层数组 = 一组词（同色同组，可含正则词）
```

- `isRegex: true` → `new RegExp(text, "iu")`；缺省 → `escapeRegExpLiteral(text)` 后字面量匹配。均为**子串匹配**（无 `\b` 边界）
- 向后兼容：`normalizeHighlightWordsByIndex()` 自动将旧字符串 / 旧 `{text}` 对象格式升级
- 全局词优先显示，文件级词补充未重复项（Set 去重）；收藏/取消收藏需从全局与本书两个作用域查找 `isRegex`，取消收藏必须**先查找再删除**

**相关文件**：`fileMetaStore.ts`（类型 + CRUD）、`utils/highlightWords.ts`（词组工具函数）、`constants/highlightColors.ts`（默认色值）、`composables/useAppHighlightTerms.ts`（侧栏动作）、`monaco/txtrHighlightMonarch.ts`（正则规则构建）、`monaco/readerInlineDecorations.ts`（token → 色值映射）、`stores/cacheStore.ts`（色值/开关持久化）。

## 染色机制：Monarch tokenizer（前景色）

高亮词染色走 **Monarch tokenizer**（`monaco/txtrTextMonarch.ts` + `txtrHighlightMonarch.ts`），不是 decorations：

- token 类型 `txtr.customHighlight.{index}`，经主题规则映射为**前景色**
- 不存储匹配位置，每次 model 变化实时重新分词；仅覆盖可见行（虚拟滚动）
- 优先级：长词优先，同长则色索引小者优先；root 正文先括号开符再高亮词，引号/括号内高亮词优先于兜底
- **Monaco model 只存纯文本**；`monaco.editor.tokenize()` 公共 API 返回的 token type 会自动追加语言 ID 后缀（如 `txtr.punctuation.txtr-text`），匹配色值映射前须去后缀

与搜索高亮（`model.findMatches()` + decorations，**背景色** + overviewRuler 指示条 + 全文位置）是两套完全不同的机制。

### 编辑模式实时染色

- 编辑模式下高亮词规则仍启用，Monarch 随输入实时重新分词染色
- 只读模式匹配**转换后的展示层文本**（简繁/全半角转换后异步匹配）；编辑模式 `applyConvert = false`，直接匹配磁盘原文
- 编辑态匹配数重统计：`editorContentChangeEpoch` 计数器随 `onDidChangeContent` 递增，`currentFileHighlightTerms` 依赖该计数器触发 `countHighlightTermMatches()` 重算

## 匹配三场景

| 场景 | 方法 | 引擎 | isRegex |
|------|------|------|---------|
| 正文染色 | Monarch tokenizer | 正则（`isRegex` 控制） | 跟随词 |
| 侧栏匹配数 | `model.findMatches(词, false, ...)` | 字符串 | 不跟随 |
| 点击跳转 | `jumpToNextInlineSearchMatch(词, { useRegex })` | 字符串（`useRegex` 控制） | 跟随词 |

匹配数统计必须等文件**流式加载完成**（`streamFile` → `onStreamEnd` 后 `setFullText()`）：composable 的 watch 依赖列表必须包含 `deps.loading`，且 `immediate: true` 首次执行时 `readerRef` 为 null，需容错。

## 查找导航

- **左键（查找下一个）**：`jumpToNextInlineSearchMatch`（内联搜索，不开搜索框）。`jumpToPrevInlineSearchMatch` 从未正常工作，已移除
- **右键（查找上一个）**：`openFindWithSearchString(q, isRegex, "prev")`（Monaco 原生搜索框 + `direction: "prev"`）
- 邻接单字符匹配跳过 bug：文本 `33333` 搜 `3` 会跳过紧邻匹配——根因是 `findIndex` 用 `r.startColumn > pos.column`，而单字符邻接匹配的 `endColumn == 下一个 startColumn`；修复（`157ec4a`）：改 `>=` 并用 `inlineSearchCurrentMatch` 排除当前匹配防原地踏步

## 一键染色（分组多色）

- 按 `colorIndex` 分组，每组用该组**已有色值**（非随机色）给滚动条 `overviewRuler.color` 染色，实现多色指示
- 点击单个词 / Ctrl+F 搜索会清空 `inlineSearchGroups` 切回单组染色——这是期望行为（分组状态非空走分组，单组动作先清空再染色）
- header 布局决策：「一键染色」从更多菜单移到 header 直出（`highlightPanelRef.colorAllHighlights()`）；「AI 检索」响应式收纳方案已放弃回退（侧栏最小宽度 250px 下 4 个按钮放得下）

## 拖拽排序的两个坑（2026-10-08 修复）

**列表拖放 isRegex 丢失**（HighlightListPanel 自有 HTML5 drag）：
- `DragPayload.storedTerms` 是 `string[]`，isRegex 在 dragstart 时就丢；跨组合并/拆分因按 `storedTerms` 从存储定位原始 `HighlightWord[]` 而天然保留
- 唯一写回丢失点在 `commitGroupTermOrder`：必须按 text 从 `item.storedWords`（行模型自带，`buildHighlightListTerms` 填充）找回原对象再 emit，**不要从裸 string 构造 HighlightWord**

**编辑面板拖拽乱序**（HighlightTermEditModal + SortableJS）：
- 根因：`v-for` 的 `:key` 从上游稳定文本 key 改成了索引 key。SortableJS 已物理移动 DOM，索引 key 下 Vue diff 原地 patch 内容导致错位
- 修复：组内 text 唯一（`normalizeHighlightGroup` 去重保证），必须用 `:key="term.text"` 稳定 key。任何 SortableJS 容器内的 Vue 列表都要用稳定 key

**关联陷阱**：SwitchToggle 的 `@update:model-value` 不能加 `.stop` 修饰符（emit 的是数据对象非 DOM 事件，`stopPropagation is not a function` 崩溃）。

## 迁移史（历史记录）

1. **`regex:` 字符串前缀**（最早期）→ 2. **`HighlightWord {text, isRegex}` 字段**（`normalizeHighlightWordItem` 兼容旧字符串）→ 3. **词组重构合并**（#56 incoming，内存退化 `string[][]`，isRegex 一度丢失，曾用 `pendingRegexGroups` 模块级 Map 过渡——因 debounce 不可靠废弃，再改 `FileMetaRecord._highlightRegexFlags` 侧挂方案）→ 4. **最终态 `HighlightWord[][]`**（内存与存储统一，`_highlightRegexFlags` 已从代码移除）。

教训：`normalizeRecord`/`upsertFileMetaRecord` 的 merge 会丢弃未显式列出的字段；侧通道 Map 在 debounce 持久化下不可靠。

## 导出染色 HTML 方案（已确认）

decorations 与 DOM innerHTML 均不可行（前者运行时 UI 层，后者受虚拟滚动限制仅 ~50-100 可见行）。确认方案：

1. `model.getValue()` 一次性取全文（`\n` 分行）
2. 遍历高亮词 `model.findMatches()` 取全部匹配位置（Monaco 1-based 行号一致，列号减 1 转 0-based）
3. 全文直接渲染（`\n` 保留换行），匹配位置 `<span data-c="色值索引" style="background:色值">` 包裹
4. 色值数组与内嵌 JS 随 HTML 输出，页面加载时遍历染色
